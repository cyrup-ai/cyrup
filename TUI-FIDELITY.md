# TUI Presentation-Fidelity Backlog — `cyrup-tui` vs pi v0.84.1

Read-only audit. Every row below was verified on both sides against `git -C pi show v0.84.1:<path>` and the live `crates/cyrup-tui/` tree. `F<n>` tags are the audit finding IDs — keep them in commit messages so nothing gets re-filed.

---

## 1. Headline

**cyrup's TUI is roughly 150 verified divergences away from pi's rendered output.** They are not exotic: they concentrate in four repeatable mistakes.

1. **Vertical rhythm is systematically ~2 rows tighter than pi's.** Every tool block, every user message and every `[skill]`/`[branch]`/`[compaction]` block loses the tinted blank row above and below its content (`box.ts:106-119` vs `transcript.rs:1127-1137`). Every assistant reply loses its leading blank row (`assistant-message.ts:100-102` vs `transcript.rs:1860`). Every bordered dialog loses 2–5 `Spacer(1)` rows (`session-selector.ts:735-747` etc. vs `selector.rs:423-431`). The whole UI reads as a dense wall where pi breathes.
2. **Text wraps outside its own padding**, so wrapped rows lose their indent.
3. **Colour is resolved through the wrong accessors** — `dim_style()` never reads the `dim` token, `error_style()` bakes in bold, table chrome gets `mdHr`/`mdHeading` where pi emits no colour at all.
4. **cyrup draws things pi does not** (`you: `/`assistant: ` labels, a `› ` editor prompt, a `▌` streaming caret, a `selectedBg` bar on every list) and **omits things pi always draws** (hint rows on seven dialogs, search boxes on three, the footer's context-usage segment, `/resume`'s tree connectors).

### The one change to make first

**Move wrapping inside the padded render — `transcript.rs:1815 pad_lines` + `markdown::render` (F26 / F43 / F131 / F144, plus the list hanging indent).**

pi wraps at `contentWidth` *first* and then prefixes the margin to every produced row (`markdown.ts:322` → `:329-340` `leftMargin + line + rightMargin`). cyrup inserts the indent into the **logical** line only (`transcript.rs:1815-1823` `line.spans.insert(0, Span::raw(indent))`) and lets `Paragraph::new(lines).wrap(Wrap { trim: false })` (`transcript.rs:2009-2011`) do the wrapping afterwards at full frame width.

Result: on any message longer than one terminal row — which is most of them — row 1 starts at column 1 and rows 2..N start at column 0, and no row has a right margin. A ragged left edge on nearly every turn is the single most "unfinished-looking" thing in the UI, and it is one root cause behind five separate findings plus the list-marker hanging indent.

Cheapest high-payoff change, if you want a win in one line first: **`theme.rs:292-299 dim_style()`** (F1) — 29 call sites, wrong in both themes, near-black in light.

## 2. Theme and colour

**Good news first, so nobody wastes a day there:** the palette *data* is clean. `cyrup-resources/src/theme.rs:518-600` (dark) and `:602-684` (light) were diffed token-by-token against `pi/…/theme/dark.json` and `light.json` — all 50 shared tokens, `vars` and `export` blocks match exactly. The light theme is fully present and `ThemeController` (`cyrup-tui/src/theme.rs:990-1080`) faithfully ports `resolveThemeSetting` / terminal-background detection. **"cyrup ships one dark palette" is false.** There are also **no hardcoded RGB colours in any renderer** — `grep "Color::"` over `crates/cyrup-tui/src/*.rs` finds only `Color::Reset` equality tests in `image.rs` and `unwrap_or(...)` fallbacks in `theme.rs`.

The damage is entirely in **style construction**: wrong accessor, or an SGR attribute added that pi never emits.

## 5. Systemic issues

Five root causes account for roughly two-thirds of the table rows above. Fix these five and whole columns collapse.

### SYS-1 — `dim_style()` resolves the wrong thing
`theme.rs:292-299` applies `Modifier::DIM` over the `text` role instead of returning the `dim` role colour. **29 call sites.**
**Subsumes:** T1, C3 (partly), X4 (partly), S4, S18's symptom, and the "hint rows are the wrong colour" half of F80's eight listed consumers (`selector.rs:673`, `settings_selector.rs:205,331`, `session_selector.rs:275,303`, `config_selector.rs:357,386`, `overlay.rs:161`).
**Worst in light theme,** where it substitutes near-black `#1f2328` for pi's grey `#767676`.

### SYS-2 — wrapping happens outside the padded component
`markdown::render` never wraps (its `width` argument only reaches `Event::Rule` and `emit_table`); `pad_lines` indents logical lines; ratatui's `Paragraph::wrap` reflows afterwards at full frame width.
**Subsumes:** L2 (F26/F43/F131), M10 (F144), M5 (the list hanging indent), and the "no right margin" half of L5 and X3.
**Fix shape:** wrap inside `markdown::render` at `width - 2*pad` and margin every produced row, mirroring `markdown.ts:322-348`. This is the one `large` item worth doing first.

### SYS-3 — `Spacer(1)` is never constructed
pi's layout language is `Spacer(1)` between every structural element; cyrup's `Layout::vertical` regions are adjacent by default and nobody added the blank rows back.
**Subsumes:** L1 (F24/F45 — Box paddingY), L3 (F41), L4 (F29/F79 — six dialogs, 2-5 rows each), C7 (F28/F69), C13 (F38/F76), E7 (F118), X3's missing blank rows, X2's missing `Spacer(1)` after the label, S20's header blanks.
**This is the single largest contributor to "cyrup looks cramped".** It is nine independent edits, none hard.

### SYS-4 — `selectedBg` is applied inverted
pi paints a selection background in exactly two components (`tree-selector.ts:748-753`, `session-selector.ts:506-508`) and never in `SelectList`. cyrup does precisely the opposite.
**Subsumes:** S1 (F6/F81/F123 — eight dialogs get a bar pi never draws), S2 (F7 + missed#1 — two places lose the fill pi does draw).
**Two edits: `select_list.rs:222…251` and the two row builders.**

### SYS-5 — `SelectList` hardcodes what pi passes per-caller
pi's `SelectList` takes a theme object (`theme.ts:1291-1314`) so `getSettingsListTheme()` can use `dim` where `getSelectListTheme()` uses `muted`, and each selector composes its own hint/description/scroll rows. cyrup's `SelectList` hardcodes `muted_style()` at `select_list.rs:178/195/258` and each cyrup selector re-implements the envelope independently.
**Subsumes:** S16's dim-vs-muted mismatch, S21 (status colour flattened into `description`), S29/S30's flattened hints, S31 (three different search prompts because `input.ts`'s single `"> "` has no shared counterpart), plus the reason L4 has to be fixed **six separate times** (`selector.rs:423`, `settings_selector.rs:187`, `:322`, `model_selector.rs:305`, `session_selector.rs:320`, `config_selector.rs:332`, `selector.rs:653`).
**Fix shape:** give `SelectList` a per-caller style struct, and extract one shared `Input` component and one shared dialog-envelope helper.

### SYS-6 (minor) — hint text is frozen at compile time
`transcript.rs:948 EXPAND_KEY`, `extension_editor.rs:44 HINT`, `model_selector.rs:196 "⇥"`, `selector.rs:671`, `settings_selector.rs:203,330` all bake key labels into string literals where pi resolves them through `keyText()` on every render.
**Subsumes:** X9's rebind half, E9's staleness half, S30's `⇥`, C11.

## 8. Killed claims

Do not re-file these.

- **F22 — hex fallback defaults in `role_style(key, default_hex)` not matching `dark.json`.** The hexes are correctly quoted on both sides, but the code is unreachable. `role_style`/`role_color` fall back only when `self.roles` lacks the key (`theme.rs:487-497`); the synthetic-empty-roles constructor (`theme.rs:189-203`) is called only from `UiTheme::dark()`/`light()` (`:161`,`:171`) with names `builtin_themes()` always resolves; and a custom theme omitting a token is blocked by `cyrup-resources/src/theme.rs:109-121`, which hard-errors on any missing `REQUIRED_COLOR_TOKEN`. The residual case — a syntactically valid string that is neither a hex nor a defined var, silently dropped by `from_theme_data`'s `filter_map` — is a real but different and far narrower bug. **No real session renders `#666666` fence borders because of this.** *(Quick-win item 8 above is still worth doing as hygiene; it is not a user-visible defect.)*
- **F90 — data-selector empty-state text.** The literals are as quoted (`selector.rs:326`, `:192`), but `SelectList::with_no_match` only renders when `items.is_empty()` (`select_list.rs:177-179`), and every production `open_data_selector` call site guards emptiness first: Logout `app.rs:3169-3175`, UserMessage `app.rs:3112-3114`, Login `app.rs:2236-2241`. BranchSummary uses `ListSelector::prompt` with three hardcoded rows (`app.rs:2455-2469`). The only empty-list path is the `other =>` fallback at `app.rs:1851`, and `open_selector` has one production caller (`app.rs:2975`, Theme). **No user ever sees the string.**
- **"cyrup ships one palette that assumes dark."** False. `cyrup-resources/src/theme.rs:518-600`/`:602-684` match `dark.json`/`light.json` token-for-token across all 50 shared tokens, `vars` and `export` blocks included, and `ThemeController` (`cyrup-tui/src/theme.rs:990-1080`) correctly ports `resolveThemeSetting` / `parseAutoThemeSetting` / terminal-background detection with high-confidence persist-back. The light-theme damage is entirely downstream of SYS-1.
- **"cyrup hardcodes colours where pi uses tokens."** Essentially false. `grep "Color::"` over `crates/cyrup-tui/src/*.rs` yields only two files: `image.rs` (2 `Color::Reset` *equality tests*, `:334`,`:339`) and `theme.rs` (37 `unwrap_or(...)` fallbacks + hex-parse plumbing). There is no `Color::Rgb` literal in any renderer. All colour drift is accessor or call-site, not magic numbers.
- **F19's `scrollbarThumb` sub-claim ("cannot even be expressed").** Overstated: pi itself defaults it (`theme.ts:164` `scrollbarThumb: bgColors.scrollbarThumb ?? bgColors.selectedBg`, and `withThemeColorFallbacks` at `:330`), so a palette omitting the key is harmless upstream. The real defect is only that no cyrup renderer reads it.
- **F39's severity.** Lowered: pi gates the scrollbar on `getFullscreenScrollbar()` (`interactive-mode.ts:873`), a fullscreen/alt-screen-only feature, and cyrup runs an inline viewport by design (`lib.rs:3`).

- **F31/F88/F124's "2 columns off" clause.** Only fires when the clamp binds (`primary_min`/`primary_max`). When `primary_min <= widest` and `widest + GAP <= primary_max`, both sides land the description at `2 + widest + 2` and agree exactly. **The scroll-window jitter is the always-on half** — that is the part worth fixing.
- **F134's scope ("the single most common shape, nearly every turn").** Wrong. - **S24's original claim that "pi never draws `⊟`". WRONG, and it cost a working feature.** The row read the guard at `tree-selector.ts:734` backwards. `foldMarker = isFolded && !showsFoldInConnector ? theme.fg("accent","⊞ ") : ""` does not mean "pi only ever shows a folded marker". `showsFoldInConnector` is `flatNode.showConnector && !flatNode.isVirtualRootChild`, so `!showsFoldInConnector` reads **"the connector did NOT already show the fold state"** — `:734` is the FALLBACK for a node with no connector to put the cell in (depth 0 / virtual-root children), and the general case is `:722`, inside the connector: `prefixChars.push(isFolded ?
